# ركن OS — مساحة العمل الموحّدة

Netlify + Neon. يجمع المنيو المصوّر وتسجيل الطلبات والمخزون والورش والتوصيل والتحصيل.

## التشغيل
- Netlify ينشر مجلد `public` ويحمّل الدالة `netlify/functions/api.js`.
- استخدم متغيري البيئة الموجودين `DATABASE_URL` و`ROKN_ADMIN_TOKEN` دون وضعهما في Git.
- طبّق `migrations/001-unified.sql` مرة قبل نشر النسخة. الترحيل إضافي ويحافظ على الطلبات والبيانات السابقة.
- `npm ci` ثم `npm test`. اختبارات Postgres محلية مع PGlite؛ اختبارات DOM مع jsdom.

## قواعد التشغيل
- المنيو يحفظ مسودة الجهاز، ويعرض مراجعة قبل الحفظ. `request_id` يمنع تكرار الطلب عند إعادة الإرسال.
- كل طلب يحتفظ بعنوان زبونه مستقلًا؛ تحديث عنوان لا يغيّر الطلبات القديمة.
- تأكيد الطلب يحجز كل القطع إن توفرت؛ وإلا يبقى بلا حجز حتى الجاهزية.
- خيارات الكونسول بالمراية وبدونها تشترك في مخزون اللون عبر `stock_variant`؛ توفر المراية نفسها يحتاج فحص الموظفة ولا يوجد مخزون منفصل للمرايات.
- الجاهزية تتطلب مخزونًا محجوزًا. الخروج للتوصيل يتطلب سائقًا وموعدًا. التسليم يخصم المخزون مرة واحدة.
- استلام دفعة ورشة يزيد المخزون الفعلي، ثم تُجهّز الطلبات من صفحة الطلب.
- المعاملات تستخدم transaction وقفلًا على عمليات الكتابة، مع revision لمنع الكتابة فوق تحديث أحدث.
- العربون والدفعات تحفظ في payments؛ driver_cash هو تحصيل السائق، والتسوية مستقلة عنه. إلغاء طلب مدفوع متوقف لحين تسوية/رد الدفعات؛ واجهة رد الأموال ليست ضمن هذه النسخة.
- المخزون المحجوز السابق يُحفظ كما هو؛ الجرد لا يستطيع إنقاص الموجود تحت المحجوز.

## حدود النسخة
رمز الإدارة الحالي مشترك وليس نظام صلاحيات أفراد. Google Sheets غير مربوط تلقائيًا. CSV ونسخة JSON متاحان للتصدير. لا يوجد استرجاع تلقائي لملف JSON. المسودة محلية وقد تحتوي بيانات زبون؛ يمكن تفريغها على الأجهزة المشتركة. صور الكونسول مرجعية وتوضح المواصفات اختلاف شكل المراية.

## التحقق
نجحت اختبارات الواجهة و43 طلب API على Postgres محلي، وتشمل فشل حفظ ذري، حجز متزامن، اختلاف النسخ، طلبات مكررة، مخزون خيارات المراية، استلام التصنيع والتسليم والدفعات. تم اختبار الترحيل الإضافي على فرع Neon منفصل. لا تمثل اختبارات DOM تحققًا بصريًا كاملًا على هاتف فعلي.
